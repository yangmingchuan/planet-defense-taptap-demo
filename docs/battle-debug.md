# 战斗 Debug 面板

战斗画面右上角提供`Debug`按钮，默认收起，点击后显示红色小字，再次点击关闭。按钮避开已知安全区与平台胶囊，横屏留黑边时贴近实际战场右边缘。面板每0.5秒更新一次文本，关闭时不读取计时、内存或渲染统计。

| 指标 | 含义与边界 |
|---|---|
| FPS、帧间隔、P95 | 使用引擎毫秒系统时钟，统计NanoVG渲染回调间隔；不使用游戏模拟截断后的dt。不等于显示器最终呈现帧率 |
| 最慢帧、>50ms次数 | 从本次开启/重新开局/焦点变化后累计；关闭重开清零 |
| 逻辑、绘制提交 | Update回调与NanoVG绘制提交的耗时，包含对应原生调用等待；不是GPU执行耗时。系统时钟不可用时仅这两项退回CPU clock，末行明确注明 |
| 怪物、守卫、弹道 | 当前数组/格子中的实体数量，含等待发射的弹道 |
| 特效、飘字、音效 | CombatFX、旧粒子、冰爆数量总和；飘字数量；当前正在播放的音效声源数量，不含配乐 |
| Lua内存 | collectgarbage("count")返回的Lua堆大小，不是浏览器/整机/GPU内存；不支持则N/A |
| 纹理、RGBA估算 | 已加载的唯一纹理句柄数及宽×高×4的理论大小，未计GPU对齐、引擎和音频开销 |
| 引擎批次、图元 | Graphics:GetNumBatches/GetNumPrimitives原样返回；可能属于上一渲染阶段，不保证完整覆盖NanoVG或浏览器合成，不能直接当作WebGL抓帧报告 |
| 画布、帧率上限 | 引擎画布尺寸与代码设置的上限；设置上限不是实测FPS |
| CPU/GPU占用 | 当前没有可用接口，固定显示N/A；不从FPS推算占用率 |

没有可靠系统时钟时，FPS、帧间隔及卡顿次数显示N/A，不用CPU clock冒充实际帧率。切到后台清空采样窗口并暂停采样，避免把用户离开时间算作卡顿。

实现：`scripts/BattleDebug.lua`集中采样和UI；`main.lua`仅接入输入、生命周期及Update/Render计时。测试：`tests/battle-debug.lua`检查开关、点击不穿透、200ms卡顿不被截断、缺失接口及布局边界；`tests/render-debug.cjs`生成四种尺寸布局校样，其数据为排版用固定值，不是性能实测。

排查时分别记录刚开局、召唤3名角色后、怪物密集时、大招期间的面板截图。同一浏览器、同一预览尺寸比较，重点看FPS、最慢帧、逻辑和绘制提交是否随角色增加而明显变化。
