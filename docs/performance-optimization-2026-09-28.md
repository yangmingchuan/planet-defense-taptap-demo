# 启动与战斗性能优化记录

日期：2026-09-28。此文记录已实施的负载控制与可复现检查；不是实机帧率报告。

## 问题与处理

- 旧版 `Start()` 在首页一次加载155张图，包括所有怪物动作和三个职业共54张攻击帧；新版首页只加载47张必要图，怪物和所选队伍可用攻击帧开战时按需加载。冰法使用稳定立绘、不加载未播放的攻击帧；二级双人沿用一级帧；Boss复用肉盾头像同一NanoVG句柄。
- 战斗资源每次Update最多准备2项，准备期间不推进波次和战斗；资源已缓存的再次挑战不重复加载。音频在战斗准备阶段才加载，首页不解码整首音乐。
- 首次首页帧率上限30，战斗60，失焦/最小化10；失焦时停止音频和模拟，恢复后延续原对局。引擎提供的`SetMaxFps`、`SetMaxInactiveFps`、`SetPauseMinimized`被调用，但浏览器端是否严格执行还需实机测量。
- 首页布局只有视口或安全区变化才重建；安全区稳定时每0.5秒复查一次，避免逐帧调用原生安全区API。
- 受伤或Boss显示血条，满血普通怪物暂不显示。单次爆炸碎光的8根线条合并为一次NanoVG描边，保留原有弹幕、怪物数量与伤害逻辑。
- `Stop`时注销事件订阅、逐一释放唯一纹理句柄，避免反复打开后重复订阅或重复释放。

## 量化边界

- `tests/resource-budget.cjs`对比同一个资源目录与上一版提交`55e8b8a`：首页纹理创建从155减至47；按PNG尺寸乘4计算的理论RGBA占用由53.87 MiB降至16.81 MiB，约减少69%。这是纹理估算，不包含GPU对齐、引擎/浏览器运行时、音频或历史资源包体，也非Activity Monitor实测。
- `tests/performance.lua`验证600帧首页布局调用、安全区轮询、42个Update完成首战资源准备且每次最多2项、失焦暂停/恢复、再战不重复加载、纹理去重销毁和描边次数。42个Update在30FPS理想条件下约1.4秒，不是实际加载时长保证。
- `tests/battle-audio.lua`验证音频只在准备时加载5项，重复调用不重新读取；原战斗回归与五组首波种子继续通过。
- `maker-lua-lsp`被调用，但本机安装缺少`emmylua_check`而无法完成静态诊断；Lua脚本执行回归通过不能替代LSP错误检查。

## 后续实测

在Maker预览与手机上分别记录首页加载耗时、30秒空闲CPU/GPU、怪潮第六至十波帧率、失焦后CPU、返前台后音频与画面是否恢复。若Chrome标签仍拖慢全机，再考虑对高密度场景进行视觉层级自适应，不能直接降低游戏伤害或丢弃弹道。
